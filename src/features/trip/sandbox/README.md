# 출장수당 화면 샌드박스 (로컬 시험용)

브라우저에서 직접 눌러 보는 환경입니다. **메모리 저장소만** 쓰고 DB·네트워크·기존 앱 코드와 연결되지 않습니다. 새로고침하면 데이터가 사라집니다.

```
npx vite --config src/features/trip/sandbox/vite.config.ts
→ http://localhost:5199
```

상단 띠에서 사용자(직원 A / 동행 B·C / 관리자), 기능 스위치, 달력 검증 표시를 바꿉니다. 같은 저장소를 공유하므로 직원으로 제출하고 관리자로 바꿔 검토할 수 있습니다.

## 수동 점검 순서 (도입 체크리스트 B5~B7 과 같은 사례)

| # | 조작 | 기대 |
|---|---|---|
| 1 | 스위치 둘 다 끔 → 직원/관리자 화면 | "아직 열리지 않았습니다"만 보임 |
| 2 | employeeForm 켬 → 근무 신청 → 출장 → 새 신청. 대전, 당일, 현장 08:00~17:00, 점심 사용 | 미리보기 **출장 4시간 확정**, 표준 이동 06:00~08:00 / 17:00~19:00. 달력 미검증 경고 |
| 3 | 저장하고 계속 → 제출 | 상태 제출됨. 수정 버튼 사라짐, 신청 취소만 남음 |
| 4 | 새 신청, 숙박 월~수, 화요일 08:00~19:00 | 화요일 "숙박 출장 중간일", 연장 2시간 **관리자 확인 필요** |
| 5 | 저장 후 동행 출장에서 이동행 선택 → 초안 보내기 → 사용자를 이동행으로 바꿈 | 목록에 "동행자가 보낸 초안". 열어서 점심 해제 → 저장 → 제출 |
| 6 | 사용자를 관리자로. adminReview 켬 | 제출됨 목록에 2~3건, 확정/제안값 칸 분리, 확인 항목 수 |
| 7 | 중간일 건 검토 → 승인 버튼 비활성 사유 확인 → E5·달력 미검증 체크 → 승인 | 이력 탭에 "승인 당시 계산 결과 보존됨 — 현재와 같음", 정산 미리보기에 제안값 보류·급여 미반영 |
| 8 | 다른 제출 건 → 입력값 수정(사유 입력) → 승인 | 수정 이력 전/후 표시, 새 계산으로 승인 |
| 9 | 직원으로 돌아가 승인된 건 취소 시도 | "취소할 수 없는 상태입니다" |
| 10 | 브라우저 창 두 개로 같은 초안을 열고 각각 저장 | 늦은 쪽에 "다른 곳에서 먼저 저장되었습니다 → 새로 불러오기" |
| 11 | 모바일 폭(≤ 420px)으로 줄임 | 한 열, 하단 고정 버튼, 입력 44px |

## 자동 브라우저 테스트(Playwright)에 대해

지금은 넣지 않았습니다. 넣으려면 `@playwright/test` devDependency 와 브라우저 바이너리 설치가 필요해 `package.json`·`package-lock.json` 이 바뀝니다 — 사용자 승인 후 진행합니다. 위 표가 그 테스트의 시나리오 초안입니다. 현재 자동 테스트는 같은 흐름을 `screens/__tests__/flows.test.ts`(화면이 부르는 함수를 같은 순서로 호출)와 `screens.test.tsx`(서버 렌더 문구)로 덮습니다.
