## 3. Git 자동 배포 회귀 방지

### 현재 상태
- `origin/master` = 로컬 master = `06f610a`. 두 핫픽스는 그 위에 **선형**으로 쌓여 있다: `06f610a → 9f9fd1f(급여명세서) → 3fd17c9(D14)`.
- 따라서 "두 수정만 반영한 통합안" = **fast-forward**. 별도 병합·충돌 해소가 필요 없고, 결과는 지금 Production 과 바이트 단위로 같은 커밋이다.
- 로컬 브랜치 `master-hotfixes-20261103` → `3fd17c9` 를 만들어 두었다(작업트리 없음, 참조만). 변경 파일은 `src/App.tsx`(7줄)·`src/pages/DashboardPage.tsx`(191줄)·`src/pages/RequestPage.tsx`(3줄) 세 개뿐이며 출장·secpatch·master 미커밋은 포함되지 않는다.
- 검증은 `busungtk-overtime-hotfix-d14`(같은 커밋)에서 완료: tsc 0, lint 기준 파일과 동일, 빌드 성공, 핫픽스 정적 검사 10/10, 서빙 번들 불변식 통과.
- 보존: master 미커밋 42건·secpatch 미커밋 38건은 각자 작업트리에 그대로 있다(이 작업은 두 트리를 건드리지 않음).

### 위험
Vercel Git 연동은 **master 로 push 되면 master 를 Production 에 자동 배포**한다. 지금 master 에는 두 핫픽스가 없으므로, 누군가 master 를 push 하면 급여명세서 노출·전체 직원 조회 코드가 다시 배포된다(10-15 회귀와 같은 경로). 008b 가 적용돼 DB 는 전원 행을 더 주지 않지만, 옛 코드가 `employees` 를 읽으면 그룹 직원 선택이 비고 급여명세서 카드는 다시 나타난다.

### 제거 방법 (승인 필요, 권고 순서)
1. **origin/master 를 `3fd17c9` 로 fast-forward push** — `git push origin master-hotfixes-20261103:master`. 선형이므로 force 가 필요 없다. Git 연동이 master 를 자동 배포하지만 그 코드는 지금 Production 과 동일하므로 무해한 재배포가 된다. 그 뒤부터 master = Production.
2. push 직후 `vercel inspect busungtk-overtime-beta.vercel.app` 로 alias 가 새 배포(또는 기존 `dpl_5zAwJ7Xz…`)를 가리키고 서빙 번들 불변식(`"/payslips"` 0, `employees_directory` 1)이 유지되는지 확인.
3. master 작업트리의 미커밋 42건은 push 뒤 `git pull --ff-only` 로 기준을 올린 뒤 이어서 작업(DashboardPage 주석 충돌 가능 — T7 계획 문서의 분석대로 secpatch 판 채택 권장).
4. Production Branch 변경은 권장하지 않음: `hotfix/d14-employees-directory` 는 원격에 없어 바꾸면 Git 트리거 배포가 전혀 일어나지 않고, 뒤에 push 하면 그 브랜치가 운영 기준이 돼 master 와 영구 분기한다. 1번이 더 단순하고 되돌리기 쉽다.
5. 자동 배포를 잠시 끄는 방법(Vercel 프로젝트 → Git → Ignored Build Step 또는 연동 해제)은 1번 전까지의 임시 안전장치로만.
