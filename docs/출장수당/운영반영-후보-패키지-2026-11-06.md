## 5. 호환성 (배포·적용 순서)
- **DB 먼저, 코드 나중(계획)**: DB 가 먼저 바뀌어도 현재 Production(`9814ca1`)은 정상 — 직원 저장은 `position` 을 보내지 않고, `list_all_employees()`·`select *` 는 칼럼이 늘어도 호환, 재직 변경은 서버 API(013 호환). 로컬 시험 `t5-sql` 5-3·5-4 절과 운영 상태 재시험이 이를 확인한다.
- **코드가 먼저 나가고 DB 가 없는 경우**: 출장 메뉴는 코드 스위치 OFF 라 호출이 없고, 직원관리 화면은 `position` 칼럼이 없으면 보내지도 보이지도 않는다(`integration-guard` 테스트).
- 코드 배포 후 DB 와 규칙 버전 일치: `trip_active_rule_version()` = 서버 번들 `RULE_VERSION`(t5-sql 1절에서 확인). 기능이 OFF 인 동안은 영향 없음.

## 6. 적용 전 백업·검증·장애 대응
- 단일 실행본은 **스스로 사전 조건을 검사**하고 하나라도 다르면 아무것도 바꾸지 않고 중단한다: PostgreSQL 15 이상, `holidays`·`trip_*` 객체 없음, `employees.position` 없음, 006(역할 보호)·007(is_active 판정)·008(직원 명부 뷰)·011(employees 최소 권한)·012(백업 테이블, anon 실행 0)·013(재직 상태 가드) 적용됨.
