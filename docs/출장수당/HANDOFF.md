- DB(020·030): `trip_view_grants`·`trip_view_grant_history`·`trip_set_view_grant`·`trip_has_view_grant`·`trip_is_admin`, `trip_can_view_all = admin or grant`. 쓰기·승인 RPC 는 admin 만(변경 없음). 스위치 OFF 면 권한이 있어도 0행. 클라이언트(`client/`): `viewGrantState·viewerQueue·viewerDetail·viewGrants·setViewGrant`. 화면: `TripViewerScreen`(읽기 전용, `AdminTripReview mode="viewer"` + `ClaimReviewDetail readOnly`), `TripViewGrantsAdmin`(admin, 부여·회수·사유). 글루(integration): `/trip/all`, `/admin/trip` "조회 권한" 탭, 사이드바 "출장 내역 조회" 는 서버 권한(`useTripViewGrant`)이 있을 때만.

- **항상 입력:** 지역, 일정(당일 / 숙박 기간), 현장 작업 시작·종료, 점심 사용(기본값 "사용").
- **자동 처리:** 평일·토·휴일 구분(공휴일 테이블), 근무 유형, 표준 편도시간, 신청 마감일.
- **상황별 입력:**

| 조건 | 추가 입력 |
|---|---|
| "사무실 근무 후 출발" 선택 | 사무실 근무 시각 |
| "현장 추가" 선택 | 추가 현장 |
| 작업 시각이 없음 | 사유 |
| 이동과 작업 사이가 1시간 이상 빔 | 회사 지시 대기였는지 |
| 18시 전 종료, 근무 8시간 미만 | 회사 지시 퇴근인지 |
| 8시간 넘게 근무했는데 점심 외 휴게가 없음 | 휴게 |
| 근거리 현장 | 사무실 집결 지시 |
| 제주 | 증빙과 실제 시각 필수 |
| 해당 시 | 경유·지연 사유 |
| 마감일 지남 | 기간 외 사유 |

- **실제 출발·도착 시각:**
  - **빈칸으로 둡니다. 표준시간을 실제 기록으로 저장하지 않습니다.**
  - 빠른 입력: 동행자 기록 불러오기, 채널톡 완료보고 시각 참고 표시(자동 입력 아님).
  - "기억 안 남"을 고르면 빈 값으로 두고 관리자 확인 대상이 됩니다.
  - 출처를 기록합니다: 본인 / 동행 복사 / 관리자 / 외부.
- **미리보기:** 출장·연장·야간·휴일 시간, 계산에 쓴 표준 이동 구간, 확인 필요 사유를 보여 줍니다.
- **동행:** 초안 보내기 → 동행자가 각자 확인하고 제출합니다. 제출하지 않은 초안은 급여에 반영되지 않습니다.

### 5-2. 관리자 승인

- 1단계: 기존 승인 화면에 "출장" 탭을 추가합니다.
- 2단계: 야근과 출장을 함께 보는 "근무 승인함"(읽기 전용 통합 조회 RPC)을 만듭니다.
- **목록:** 출장·연장·야간·휴일을 칸으로 나눕니다. 제안값은 다른 색으로 표시합니다. 확인 필요 사유로 걸러 볼 수 있습니다.
- **상세 탭:** 입력값 / 계산 근거(규칙 버전, 표준 이동 구간) / 법정 비교 / 동행자 비교 / 이력.
- **자동 확인 표시:**
  - 미확정 규칙 적용
  - 실제 시각 누락
  - 실제와 표준 차이 1시간 이상
  - 동행 불일치
  - 같은 날 중복 신청
  - 주간 한도
  - 토·일·공휴일
  - 제주, 경유·지연
  - 기간 외 신청
- **수정:** 입력값만 고칠 수 있습니다. 사유는 필수이고, 원래 값과 이력은 보존합니다. 고치면 다시 계산합니다.
- **승인:** 인사담당 1차 → 대표 최종 (경로는 [미결정]).
  - 승인은 **특정 계산 결과에 고정**됩니다. 화면을 연 뒤 입력이 바뀌었으면 승인이 거부됩니다.
  - 확인 표시가 남아 있으면 승인할 수 없습니다.

**계산 결과 4그룹 (서로 옮기지 않음)**
1. 회사 출장수당 인정: 출장시간, 그중 야간 이동
2. 회사 연장수당 인정: 연장시간, 그중 야간 연장

## 7. 신청부터 급여 반영까지

1. **작성:** 직원이 근무를 마친 뒤 입력합니다. 동행자에게는 초안이 갑니다.
2. **자동 계산:** 서버가 그날 적용되는 규칙 버전으로 계산합니다. 미리보기도 같은 엔진을 씁니다. 미확정 규칙에 걸리면 제안값과 확인 표시가 붙습니다.
3. **제출:** 입력값과 계산 결과를 함께 저장합니다. 증빙과 기한 규칙은 기존 것을 재사용합니다.
4. **1차 검토:** 확인 표시를 처리합니다(확정 / 수정 / 반려).
5. **대표 승인:** 승인한 계산 결과가 고정됩니다.
6. **월 정산:** 승인된 확정값만 들어갑니다. 아직 확정되지 않은 제안값은 보류합니다.
7. **마감:** 마감한 달은 잠깁니다. 이후 수정이나 승인 취소는 다음 달 조정 행으로 처리합니다.

규정이 바뀌면 새 규칙 버전에 적용 시작일을 정합니다. 지난 계산 결과는 바뀌지 않습니다.

**시뮬레이션 요약**

| 상황 | 결과 |
|---|---|
| 팀장님 기준 사례 | 자동 계산 → 승인 → 반영 |
| 숙박 중간일 | 제안값 → 확정 후 반영 |
| 동행자가 지역을 잘못 고름 | 불일치 표시 → 수정 이력 남기고 다시 계산 |
| 최종본 사례 16 | 자동 계산 |
| 다음 날 09시를 넘긴 작업 | 제안값, 주 한도 표시 |
| 제주, 일요일 | 항상 확인 |
| 같은 날 일반 야근과 출장 중복 | 경고, 정산 UNIQUE 제약으로 이중 지급 차단 |
| 실제 시각 누락 | 회사 인정분은 반영, 법정 값은 "기록 없음" |

## 13. 문서 Git 추적 — 추천안 (결정은 사용자)

현재 이 문서는 **master 작업트리의 미추적 파일**이고 trip 작업트리에는 없다. 그대로 두면 master 작업트리 정리 시 유실될 수 있다.

| 안 | 방법 | 장점 | 위험 |
|---|---|---|---|
| **A (추천)** | 이 폴더(`docs/출장수당/`)를 trip 작업트리로 복사해 `feature/trip-allowance` 에 `docs:` 커밋. master 쪽 사본은 그대로 둠 | 코드와 같은 브랜치에서 이력 관리. master 미커밋분을 건드리지 않음 | 두 사본이 갈라질 수 있음 → 이후 수정은 trip 쪽만 하고 master 사본은 참고용으로 표시 |
| B | master 에서 이 문서만 `docs:` 커밋 | 한 곳 | master 에 미커밋 42개가 있어 `git add` 범위 실수 위험. master 커밋은 Vercel 자동 배포 트리거 가능성(문서만이라도 빌드가 돎) |
| C | 커밋하지 않고 백업만 유지 | 변경 없음 | 유실 위험 지속 |

A 를 택하면 `T5-DB-초안/`, 공지문 초안, 도입 체크리스트도 같은 커밋에 넣을 수 있다. 어느 안이든 **원격 push 는 별도 승인**.
