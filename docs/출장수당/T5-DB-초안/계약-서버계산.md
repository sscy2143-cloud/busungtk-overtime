# 서버 재계산 계약 (TypeScript ↔ SQL) — 2026-11-02

권장안 B(`../T5-보안검토_계산결과조작.md`)를 구현하는 양쪽이 따르는 계약. **SQL 초안(040 등)과 `src/features/trip/server/`·`api/trip-compute.ts` 는 이 문서와 일치해야 한다.** 바꿀 때는 양쪽을 같이 바꾼다.

## 0. 원칙

1. 클라이언트(브라우저)는 **입력 원본만** 보낸다. 계산 결과·규칙 버전·지역 표준시간·역할은 보내지 않고, 보내도 서버가 무시한다.
2. 계산은 Vercel Function `api/trip-compute.ts` 가 **DB 에 저장된 입력**으로 `computeClaimDays`(`src/features/trip/data/compute.ts`)를 실행해 만든다. 엔진 상수(`REGIONS`, `RULE_VERSION`)는 서버 번들의 값이다.
3. 계산 결과 저장은 **service_role 전용 RPC** 로만 한다. anon/authenticated 는 EXECUTE 권한이 없다.
4. 제출·승인은 "현재 입력에 대한 서버 계산"이 있을 때만 된다. 없거나 오래됐으면 `CALC_STALE_OR_UNTRUSTED`.
5. 기능 스위치 OFF 면 쓰기·계산·조회 전부 거부.

## 1. 호출 흐름

```
브라우저 ─ anon key + 사용자 JWT ─▶ RPC trip_create_claim(p_header, p_entries, p_employee_id?)   → {id, version}
브라우저 ─ anon key + 사용자 JWT ─▶ RPC trip_update_draft(p_claim_id, p_expected_version, p_header, p_entries) → {id, version}
브라우저 ─ Bearer <사용자 JWT> ─▶ POST /api/trip-compute  { "claimId": "<uuid>" }
    함수: JWT 검증 → employees.role → 기능 스위치 → 본인 건/관리자 → DB 입력 읽기 → computeClaimDays
          → RPC trip_store_server_calcs(...)  (service_role)
    응답: { ok: true, claimId, ruleVersion, calcIds: { "<day_id>": "<calc_id>" }, reviewCodes: { "<day_id>": [..] } }
          | { ok: false, code, message }   (HTTP 401/403/404/409/422/500)
브라우저 ─▶ RPC trip_submit(p_claim_id, p_expected_version)      — 서버 계산이 현재 입력과 맞아야 함
관리자  ─▶ RPC trip_admin_adjust_day(...) → POST /api/trip-compute → RPC trip_review(...)
```

## 2. DB 객체 계약

### 2-1. 테이블 변경 (010)

| 객체 | 변경 |
|---|---|
| `trip_rule_versions` | `is_active boolean not null default false` 추가. 부분 UNIQUE 인덱스 `(is_active) where is_active` (활성 1건). seed 행을 `is_active = true` 로 |
| `trip_day_calcs.engine_source` | `check (engine_source in ('server', 'edge'))`, **default 제거**. `'client'` 불허 |
| `trip_day_calcs` | 기존 불변 트리거 유지. 추가 CHECK: 수치 칼럼 `>= 0`, `trip_hours <= 8`, `overtime_hours <= 24`, `holiday_* <= 24` |
| `trip_claim_days` | BEFORE UPDATE 트리거: 소속 claim.status ∈ ('approved','rejected','cancelled') 이면 `LOCKED` 예외 (is_removed/removed_at 변경 포함) |
| `trip_reviews` | BEFORE INSERT 트리거: `calc_ids` 의 모든 원소가 `trip_day_calcs.claim_id = new.claim_id` 인지 → 아니면 `REVIEW_CALC_MISMATCH` |

### 2-2. 함수

**`public.trip_active_rule_version() returns text`** — stable, security definer. `is_active` 행의 version. 없으면 null.

**`public._trip_calc_is_current(p_day public.trip_claim_days) returns boolean`** — 내부용.
최신 calc(seq desc) 가 존재하고 `engine_source = 'server'` 이고 `day_revision = p_day.revision` 이고 `entry_snapshot = p_day.entry` 이고 `rule_version = trip_active_rule_version()` 이면 true.

**`public.trip_store_server_calcs(p_claim_id uuid, p_claim_version integer, p_rule_version text, p_calcs jsonb, p_computed_by uuid) returns jsonb`** — security definer. **service_role 만** (`revoke execute from public, anon, authenticated`; `grant execute to service_role`). 함수 첫 줄에서 `coalesce(current_setting('request.jwt.claims', true)::jsonb ->> 'role', current_setting('role', true)) = 'service_role'` 이 아니면 `FORBIDDEN`.

- `p_claim_version`: 함수가 입력을 읽은 시점의 `trip_claims.version`.
- `p_calcs`: `{ "<day_id uuid>": DayComputation & { dayRevision: number } }` — `DayComputation` = `{ classification, engineInput, result, carryIn?, carryOut? }` (TypeScript `data/compute.ts` 의 `DayComputation` 을 JSON 으로. `null` 허용 필드는 JSON `null`). `dayRevision` 은 함수가 읽은 그 근무일의 `revision`.
- 검사 (하나라도 실패하면 전체 롤백):
  1. claim 존재, `status in ('draft','returned','submitted')` — approved 등은 `NOT_EDITABLE`
  2. `p_rule_version = trip_active_rule_version()` 아니면 `RULE_VERSION_MISMATCH`
  3. 모든 키가 그 claim 의 `is_removed = false` 근무일 id, 그리고 **모든** 활성 근무일이 키에 있어야 함 (`CALC_INCOMPLETE_SET`)
  4. `p_computed_by` 가 `employees` 에 존재
  5. `classification.missing` 배열·`notices` 배열 형식. `result.ok = true` 면 `result.ruleVersion = p_rule_version`, 수치 ≥ 0, `trip.hours ≤ 8`, `overtime.hours ≤ 24`, `holiday.* ≤ 24`
  6. `engineInput.regions` (있으면) 의 모든 코드가 `trip_regions` 에 존재하고 근무일에 유효 (`effective_from <= work_date and (effective_to is null or effective_to >= work_date)`) — 아니면 `UNKNOWN_REGION`
  7. **계산-저장 경쟁 방어:** `p_claim_version = trip_claims.version`(for update 로 잠근 뒤) 아니면 `VERSION_CONFLICT`
  8. 각 근무일 `p_calcs[day].dayRevision = trip_claim_days.revision` 아니면 `VERSION_CONFLICT` — 함수가 입력을 읽은 뒤 직원·관리자가 입력을 바꿨으면 옛 입력으로 낸 계산이 저장되지 않는다 (화면은 다시 계산)
- 저장: `entry_snapshot := day.entry`(DB 값), `day_revision := day.revision`, `engine_source := 'server'`, `computed_by := p_computed_by`. 직전 calc 와 동일(기존 비교 로직)하면 새 행 없이 기존 id 반환.
- 반환: `{ "<day_id>": "<calc_id>" }`

**공개 RPC 변경 (040)**

| RPC | 변경 |
|---|---|
| `trip_create_claim(p_header jsonb, p_entries jsonb, p_employee_id uuid default null)` | `p_calcs` 제거, `_trip_apply_calcs` 호출 제거. 반환 `{id, version}` |
| `trip_update_draft(p_claim_id, p_expected_version, p_header, p_entries)` | 동일. 시작에 `select … from trip_claims where id = p_claim_id for update` |
| `trip_submit(p_claim_id, p_expected_version)` | `for update`. 모든 활성 근무일에 `_trip_calc_is_current` true 이고 `missing_count = 0` 이고 `result_ok` → 아니면 `CALC_STALE_OR_UNTRUSTED`(계산 없음/오래됨) 또는 `INCOMPLETE`(입력 부족) |
| `trip_review(... action='approve')` | `for update`. `STALE_CALC` 검사 뒤에 모든 근무일 `_trip_calc_is_current` → 아니면 `CALC_STALE_OR_UNTRUSTED` |
| `_trip_store_calc`, `_trip_apply_calcs` | **삭제** (900 에서도 제거) |

### 2-3. RLS (030)

- SELECT 정책에 기능 스위치 조건 추가: 직원 정책 `… and public.trip_feature_enabled('employee_form')`, 관리자 정책 `… and public.trip_feature_enabled('admin_review')`. OFF 면 0행.
- **관리자 = `employees.role = 'admin'` 활성 사용자만** (`trip_can_view_all()`, 11-03). manager 는 직원과 같이 본인 건만 본다. REST 직접 조회로도 같은 규칙(RLS). 정책 이름은 `*_select_self` / `*_select_admin`.
- 쓰기 정책 없음(유지). `trip_store_server_calcs` 는 security definer 라 RLS 무관.

### 2-4. 롤백 (900)

새 함수·트리거·인덱스·칼럼을 역순으로 제거. 삭제된 함수(`_trip_store_calc`, `_trip_apply_calcs`)는 롤백 대상에서 뺀다.

## 3. 함수(`api/trip-compute.ts`)가 읽는 것 (service_role, 테이블 직접 조회)

| 읽기 | 칼럼 |
|---|---|
| `employees` | `id, role` (`id = auth.uid()`) |
| `trip_feature_flags` 또는 `rpc trip_feature_enabled(p_key)` | `enabled` |
| `trip_claims` | `id, employee_id, group_id, origin, header, status, version` |
| `trip_claim_days` | `id, claim_id, employee_id, work_date, entry, revision` (`is_removed = false`) |
| `trip_claim_days` (다른 신청) | 같은 직원·`work_date = 다음 날`·`claim_status in ('draft','submitted','returned','approved')`·`claim_id <> 이 claim` — 다음 날 연결용 |
| `holidays` | `holiday_date` where `is_verified` — 검증 행 0건이면 `NO_CALENDAR`(모든 날 `HOLIDAY_SOURCE_UNVERIFIED`) |
| `trip_rule_versions` | `trip_active_rule_version()` = 서버 번들 `RULE_VERSION` 이어야 함. 아니면 `RULE_VERSION_MISMATCH` (배포 불일치 방지) |
| `overtime_requests` | 같은 직원·`date` ∈ 근무일·`status not in ('cancelled','rejected')` → `'야근 HH:MM~HH:MM (상태)'` 문구로 `OTHER_REQUEST_SAME_DAY` |

쓰기는 `trip_store_server_calcs` RPC 호출 하나뿐.

## 5. 미결·주의

- 2단계 승인(K7)·관리자 본인 건 수정 금지 여부·동행자 상호 조회: 이전 초안과 같이 [미확인] 유지.
- `trip_rule_versions.effective_from` 시행일 미정 → 활성 여부는 `is_active` 로만 판단. 시행일 확정 시 유효기간 검사 추가.
- Edge Function(`engine_source='edge'`)은 CHECK 에 남겨 두지만 이번 구현은 `'server'` 만 쓴다.
