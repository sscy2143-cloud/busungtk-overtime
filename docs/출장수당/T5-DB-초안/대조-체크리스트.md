# 출장수당 DB 초안 적용 전 대조 체크리스트 (읽기 전용)

> **실행 금지 상태입니다.** 근태관리 Supabase(`wvwbaqyxztgcrkiacvql`)는 사용자가 의도적으로 일시정지했습니다. 재개는 사용자가 결정합니다.
> 재개 뒤에도 이 문서의 쿼리는 **읽기 전용(SELECT)만** 씁니다. 직원 행·급여 행 내용은 조회하지 않습니다. 개수와 구조만 봅니다.
> 결과는 이 문서 아래 "기록" 칸에 적고, 문제가 있으면 010~040 을 고친 뒤 다시 대조합니다.

## 실행 방법

- Supabase 대시보드 SQL Editor 에서 한 항목씩 실행합니다. CLI·`psql` 자동 실행은 쓰지 않습니다.
- 각 쿼리 앞에 `begin read only;`, 뒤에 `rollback;` 을 붙여 실수로 쓰기가 섞여도 반영되지 않게 합니다.

## C-2. 미커밋 마이그레이션 적용 여부

master 작업 트리에만 있는 `20260907*`, `20260916*`, `20260921*` 의 대표 객체가 운영에 있는지 봅니다.

```sql
-- 마이그레이션 기록표 (CLI 로 적용한 경우에만 남음. SQL Editor 복붙 적용이면 비어 있을 수 있음)
select version, name
from supabase_migrations.schema_migrations
where version >= '20260900000000'
order by version;

-- 객체로 직접 확인
-- 20260907000000 / 20260907010000 (증빙·마감·구두 승인)
select 'column' as kind, table_name || '.' || column_name as name
from information_schema.columns
where table_schema = 'public'
  and table_name = 'overtime_requests'
  and column_name in ('evidence_report_id', 'deadline_date', 'is_late', 'approval_route',
                      'entry_route', 'approval_method', 'verbal_approver_id')
union all
select 'table', table_name
from information_schema.tables
where table_schema = 'public'
  and table_name in ('overtime_grace',                                         -- 20260907010000
                     'admin_permissions', 'payroll_access_grants',            -- 20260916000000
                     'payroll_reauth_sessions', 'payroll_auth_lockouts', 'payroll_auth_attempts')  -- 20260921000000
union all
select 'column', 'employee_payroll_info.hourly_wage'                          -- 20260916010000
from information_schema.columns
where table_schema = 'public' and table_name = 'employee_payroll_info' and column_name = 'hourly_wage'
union all
select 'function', p.proname
from pg_proc p join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public'
  and p.proname in ('has_admin_permission', 'is_permission_admin_user', 'set_admin_permission',  -- 20260916
                    'has_payroll_reauth', 'can_access_payroll', 'current_auth_session_id')       -- 20260921
order by 1, 2;

-- 20260916020000 컷오버 여부: 기존 관리자 정책이 세부권한 기준으로 바뀌었는지
select tablename, policyname, qual
from pg_policies
where schemaname = 'public' and policyname = 'overtime_requests_select_manager';
```

| 판정 | 결과 → 조치 |
|---|---|
| `has_admin_permission` 있고 정책 qual 이 `has_admin_permission('overtime_view')` | 20260916 컷오버 적용됨. `030` 의 `trip_can_view_all()` 본문을 `has_admin_permission('trip_view')` 로 바꾸고, `set_admin_permission` 허용 키에 `trip_view`·`trip_manage` 추가하는 작업을 별도 승인으로 진행 |
| 없음 (qual 이 `is_manager_or_admin()`) | 초안 그대로 `is_manager_or_admin()` 사용 |
| `overtime_requests` 증빙·마감·구두 승인 칼럼 있음 | K11·K12 재사용 설계에 반영 (출장 `deadline_date`·`input_route` 와 의미 맞추기) |
| 기록 | |

## C-5. 테이블·함수 이름 충돌

010~040 이 만들 이름이 이미 있는지 봅니다. 하나라도 있으면 010 이 실패합니다(의도된 동작).

```sql
select 'table' as kind, table_name as name
from information_schema.tables
where table_schema = 'public'
  and (table_name like 'trip\_%' or table_name in ('holidays', 'public_holidays', 'payroll_periods', 'allowance_settlements'))
union all
select 'function', p.proname
from pg_proc p join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public'
  and (p.proname like 'trip\_%' or p.proname like '\_trip\_%')
order by 1, 2;
```

| 판정 | 조치 |
|---|---|
| 0행 | 그대로 진행 |
| `holidays` 있음 | 구조를 C-5b 로 확인. 다른 앱(공유 DB 사용 이력)이 쓰는 테이블이면 출장은 `trip_holidays` 로 이름 변경 |
| 기록 | |

## C-6. `employees` 역할 칼럼과 연결 방식

## C-9. 직원 삭제 흐름

`trip_claims.employee_id` 는 `on delete restrict` 입니다(3년 보관). 기존 앱에서 직원을 물리 삭제하는 경로가 있으면 출장 기록이 있는 직원은 삭제가 막힙니다.

```sql
-- employees 를 참조하는 FK 들의 삭제 동작 (출장 외)
select conrelid::regclass as from_table, conname,
       case confdeltype when 'c' then 'cascade' when 'n' then 'set null' when 'r' then 'restrict' when 'a' then 'no action' end as on_delete
from pg_constraint
where contype = 'f' and confrelid = 'public.employees'::regclass
order by 1;
```

코드 쪽은 `delete` 를 쓰는 직원 관리 화면이 있는지 별도로 확인합니다 (현재 앱은 `is_active` 퇴직 처리로 보임 [미확인]).

## C-10. `overtime_requests` 칼럼 (서버 계산의 같은 날 야근 조회)

v2 서버 계산 함수(`api/trip-compute.ts`)는 같은 직원·같은 근무일의 기존 야근을 읽어 `OTHER_REQUEST_SAME_DAY` 확인 표시를 붙입니다 (계약 3절). 초기 스키마 기준 칼럼이 운영에도 그대로인지 봅니다. 행 내용은 보지 않습니다.

```sql
select column_name, data_type, is_nullable
from information_schema.columns
where table_schema = 'public' and table_name = 'overtime_requests'
  and column_name in ('employee_id', 'date', 'status', 'planned_start', 'planned_end')
order by column_name;

-- status 허용값 (초기 스키마: pending / approved / rejected / cancelled)
select conname, pg_get_constraintdef(oid)
from pg_constraint
where conrelid = 'public.overtime_requests'::regclass and contype = 'c';
```

| 기대 | 5행. `date` date, `planned_start`·`planned_end` time, `status` CHECK 에 'cancelled'·'rejected' 포함 |
|---|---|
| 다르면 | 계약 3절의 조회 조건(`status not in ('cancelled','rejected')`)과 표시 문구를 함수 쪽에서 고침. SQL 초안은 이 테이블을 읽거나 쓰지 않음 |
| 기록 | |

## C-11. service_role 호출 판정과 함수 실행 권한

`trip_store_server_calcs` 는 service_role 만 실행할 수 있어야 하고, 함수 첫 줄에서 `request.jwt.claims` 의 `role`(없으면 `current_setting('role')`)이 `service_role` 인지 다시 봅니다. 운영 PostgREST·API 키 체계(기존 JWT 키 / 새 `sb_secret_` 키)에서 이 값이 기대대로 들어오는지 확인합니다.

```sql
-- 1) 역할 존재와 RLS 우회 여부
select rolname, rolbypassrls from pg_roles where rolname in ('anon', 'authenticated', 'service_role');

-- 2) Supabase 기본 함수 권한 (public 스키마 새 함수에 누가 EXECUTE 를 자동으로 받는지)
select defaclrole::regrole, defaclnamespace::regnamespace, defaclacl
from pg_default_acl where defaclobjtype = 'f';

-- 3) 적용 뒤: 권한이 계약대로인지 (anon·authenticated false, service_role true)
-- select r, has_function_privilege(r, 'public.trip_store_server_calcs(uuid, integer, text, jsonb, uuid)', 'execute')
-- from unnest(array['anon', 'authenticated', 'service_role']) as r;
```

함수 안 역할 판정은 SQL Editor 로는 재현되지 않습니다 (postgres 로 실행되어 `FORBIDDEN` 이 정상). 적용 뒤 Vercel 함수에서 실제 호출로 확인하되, 기능 스위치가 꺼진 상태에서는 `FEATURE_DISABLED` 가 먼저 나는지까지 봅니다.

| 기대 | service_role `rolbypassrls = true`. 기본 권한에 anon·authenticated 가 있으면 040 의 명시 revoke 가 필요(이미 포함) |
